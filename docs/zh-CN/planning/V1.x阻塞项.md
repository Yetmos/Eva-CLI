## 1. 文档目的与状态口径

本文只保留会阻塞 V1.x **生产能力交付或生产闭环判定**的事项。完成的仓库实现、本地回归和历史 evidence 不在本文记录；如果同一 Work Package 仍缺生产环境验证，只保留尚未解除的边界。

当前公开版本仍为 `1.11.5-alpha`。默认执行 `eva release check --output json` 的事实是：

- `status: "ready"`：当前 alpha 输入没有 required gate 被判定为 blocked。
- `warning_gates: 7`：包含 1 个 service handoff 警告和 6 个未测性能 gate。
- `closure.status: "ready_with_external_blockers"`：生产闭环仍有 5 个明确的外部阻塞项。

因此，alpha `ready` 不等于 production ready，也不能作为 publication decision。

本文件只记录以下三种未闭环状态：

| 状态 | 含义 |
| --- | --- |
| 进行中 | 实现或本地验证已经存在，但要求的生产环境 evidence 尚未齐全 |
| 未解决 | 尚未完成，但已有明确方法且不需要先获得新的外部决策或权限 |
| 阻塞 | 缺少上游逻辑项、获批决策、平台、身份、凭据、硬件或外部服务，当前不能完成验收 |

当前活跃范围映射为 7 个进行中（实施计划中的“验证中”）和 54 个阻塞，覆盖 W2 至 W10。

凡是步骤依赖操作系统服务管理器、进程身份/终止语义、文件系统安全边界、硬件权限或发行渠道，必须同时给出 Windows、macOS、Linux 三个平台的执行方法和平台验收条件。平台表中的状态只描述该平台子边界；任一平台仍为“阻塞”时，不能把所属阻塞项从本清单移除。

三平台必须分别生成原生签名和安装 evidence，再由 W10 verifier 聚合；交叉编译产物、模拟器、开发证书或本地缓存不能替代对应平台证据。

## 7. 推荐解除顺序

1. 先提供 EXT-01，在三平台完成 W2 service lifecycle/reboot/evidence，再完成 W3 identity/vault/production evidence。
2. 固定 EXT-03 server 和回收合同，收口 W4-L01/L07/L10。
3. W2/W3、EXT-02 和 EXT-08 就绪后，按 source/catalog -> KMS/AEAD -> remote readback -> trusted restore -> service handoff 推进 W5。
4. 并行完成 DEC-02/W6、EXT-04/W7、EXT-05/09/W8、EXT-06/07/W9。
5. DEC-01 批准且所有 in-scope producer/evidence 就绪后，实现 W10；publication 只能服从机器 decision。

## 8. 通用验证与更新规则

每个步骤解除前，必须同时提供目标行为、兼容契约、负向测试和要求的环境 evidence，并保持以下基线通过：

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
./scripts/validate-cli-json-contracts.ps1
./scripts/build-site-i18n.ps1
./scripts/validate-i18n.ps1
./scripts/validate-version-management.ps1
cargo run -q -- version --output json
cargo run -q -- release check --output json
```

状态更新必须遵守：

- 本地或单平台完成只能关闭对应子边界，不能代替三平台 production evidence。
- 涉及平台差异的步骤必须同时维护 Windows、macOS、Linux 三行方法和平台验收条件；缺失任一平台时，所属步骤不得标记为已解除。
- 每个包含“解决方法”的表必须在其右侧保留“操作步骤”列，至少写明准备、执行、回读/清理动作；操作步骤未完成时不得更新状态或移除阻塞项。
- 代码存在但缺真实环境 evidence 时标为“进行中”，不能从清单删除。
- 缺 external/decision/upstream prerequisite 时标为“阻塞”，并明确列出解除输入。
- 步骤达到完成标准后立即从本文删除，不保留历史段落。
- 生产 evidence 必须绑定 commit、artifact digest、environment、executor、timestamp、scope、gate result 和 remediation；未满足前版本保持 alpha。
